The thesis

In-person ID was never perfect.
AI scales the shortcuts.

A calm person who looks like a decade-old photo is good enough at a counter. Society runs on shallow identity assumptions, and AI turns every one of them into a script. We don't need to beat the clerk. We need to be at least as good, everywhere, all the time.

PoH

Proof of Human

Random actions issued when the camera opens can't be filmed in advance. Every attempt needs a real person, in real time. That's labour a fraud operation has to pay for.

PoU

Proof of Uniqueness

A 1:N search over every live selfie links one face to many documents. The next scam needs a new human, not a new PDF.

Mules

Residual risk looks like mules

Even if a document gets forged, what's left is mule economics, not AI-agent scale. Each account costs a body, and every body can only be used once.

Confidence path

A fixed sequence.
One score, server side.

There's no mid-flow exit and no oracle. The applicant finishes every step, the phone seals the session, and the server scores it once from raw signals. The phone only ever learns a route.

LAYER 3 · RANDOM CHALLENGE · PoH

Moves nobody can pre-record.

When the camera opens, the server draws 3 distinct actions, always including one head turn. A replayed clip can't know the order. Live face swaps, trained on frontal faces, lose tracking on the turn.

  • ✓
    Issued at selfie timevalid 180 s · single use · 15 s per step
  • ✓

What it stops

Eight attacks.
Eight tripwires.

BLOCKED
01

Chip downgrade

A chipped card, but the attacker takes the photo-only path.

Chip symbol detected on the card → NFC read required.
BLOCKED
02

Screen, print, colour copy

Someone else's card, replayed or printed.

Scene model, moiré, colourfulness on the still.
BLOCKED
03

Photo substitution

An impostor's face on a genuine card.

Printed portrait vs the chip's signed DG2.
BLOCKED
04

Deepfake, swap, replay

A face check passed without a live person.

Random actions, same-face frames, passive liveness.
BLOCKED
05

One face, many IDs

Mules and synthetic identities.

1:N clusters across sessions.
BLOCKED
06

Emulator, root, hooks

Everything above bypassed at the source.

Hardware attestation + boot-state consistency.
BLOCKED
07

Tampered payload

Forged signals reach the backend.

Sealed, signed, single-use challenge, rescored.
BLOCKED
08

Oracle probing

Retrying until the checks pass.

The phone only learns a route. Never a reason.

How it was validated

Real hardware.
Honest limits.

Validated

  • End-to-end sessions on a Pixel 6: 4-certificate StrongBox chain verified, unlocked bootloader reported, root caught despite hidden Magisk.
  • Four onboarding attempts by the same person linked into one face cluster.
  • Screen replay of a real card caught on device by the scene model.
  • Tablet replay on the public Silent-Face samples: face match 0.59, liveness 0.002.
  • API tests: six attack scenarios routed, audit-chain tamper detection, 1:N linking.

Next

  • Face-swap / deepfake service is a mock behind a stable contract. It needs a real detector.
  • The document agent is a stub. It has no online lookups yet.
  • Play Integrity tokens are requested but not yet verified server side.
  • Swiss CSCA chaining, Google root pinning and revocation checks are still to do.
  • Every risk weight is hand-set. Labelled sessions would let us fit them to a target APCER / BPCER.
