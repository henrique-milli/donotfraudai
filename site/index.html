How it works

Four steps. One score, on the server.

The applicant finishes every step, the phone seals the session, and the server scores it once. The phone only learns the route, never the reason.

01 · DEVICE

Real phone

Hardware key attestation, boot state, root and hook checks.

02 · DOCUMENT

Real card

Quality gates, screen and print detection, MRZ check digits.

03 · CHIP

Genuine card

NFC chip must match the print and carry the issuer's signature.

04 · FACE

Live, unique human

Random challenge, 1:1 vs the chip photo, 1:N across all sessions.

ONE PHOTO

Five layers check every frame.

Scroll to take the phone apart. Each layer comes forward so you can read it.

01 · DEVICE TRUST

Is this a real phone?

We check the hardware before trusting a pixel.

  • Hardware key attestation, bound to our challenge
  • Boot state vs attested boot catches hidden root
  • Emulators, hooks, virtual cameras
02 · CAMERA

The raw frame.

Real footage from our Pixel 6. The still is only taken after two good frames in a row.

03 · QUALITY GATES

Seven gates, live.

  • Card detected and filling the frame
  • Light, glare, sharpness
  • No fingers, portrait or MRZ readable
04 · ATTACK DETECTION

Screen, print or real?

Four checks on the still. If one misses, another catches it.

  • Scene model: physical 0.64, screen 0.00
  • Moiré and colour checks
  • Photo tampering on the portrait
05 · MRZ + CHIP

Read it, then prove it.

  • MRZ check digits must be valid
  • Chip data must match the print
  • Issuer signature verified on the chip
SEALED

Sealed on the phone, scored on the server.

Encrypted to the server and signed by the attested key. The server re-derives every score from the raw signals.

ONE SELFIE

Live. Matching. Unique.

Is it a person, is it happening now, is it the holder, and have we seen this face on another identity?

01 · DEVICE TRUST

The same attested phone.

The key that signs the challenge lives in StrongBox. A virtual camera already costs points.

02 · SELFIE

A clean, frontal face.

  • Face detection (YuNet)
  • Centered, lit, eyes open
  • Passive liveness on every frame
03 · RANDOM CHALLENGE

Moves nobody can pre-record.

Three actions drawn by the server when the camera opens, always one head turn. Live face swaps lose tracking on the turn.

04 · FACE ↔ DOCUMENT

Is it the holder? Not this time.

The selfie is matched against the chip's signed photo. In our recorded run it wasn't the card holder, and the face step went red.

05 · UNIQUENESS

One face, how many identities?

Every selfie is searched against all others. On real hardware, four attempts by one person were linked into one cluster.
